# DesignSpark 1.0 产品需求文档

版本：1.0（规划稿）  
日期：2026-11-09  
面向用户：设计学生、独立设计师及开展前期研究的设计团队

## 1. 产品定位与背景

DesignSpark 是面向设计者的设计研究与灵感辅助 Skill，将定向采集、个人作品库、结构化知识卡片和设计思维辅助串联起来。用户从一个设计问题出发，查找相关案例、理解设计方法，并将案例中的方法迁移到自己的问题中。

设计奖网站积累了丰富案例，但信息分散，网站分类与设计者的实际问题并不总是一致。单纯收藏图片容易丢失背景，批量下载又容易形成难以查找的资料堆积。DesignSpark 希望让案例从“看过的作品”变成可以检索、比较和复用的设计知识。

本文描述目标能力，不代表当前脚本已经全部实现。现有采集脚本是产品基础，动态作品库、统一卡片和启发式 Agent 仍需迭代。

## 2. 用户痛点与产品目标

| 用户痛点 | 产品目标 |
| --- | --- |
| 在不同官网反复筛选、打开和保存作品 | 根据明确条件定向采集，减少重复操作 |
| 一次采集大量资料，实际只需要少量相关案例 | 支持范围限定，优先使用本地已有资料 |
| 图片、介绍、来源分散，后续难以追溯 | 使用统一目录与卡片保存信息 |
| 日常语言难以直接对应官网类别 | 将设计需求映射为可解释的检索条件 |
| 案例看得多，却不知道如何用于自己的项目 | 提炼设计机制，提供有依据的迁移方向和验证问题 |

首版目标是完成“描述需求 → 检索或采集 → 沉淀卡片 → 比较与启发”的闭环。首版不承担完整设计方案交付、原创性鉴定或获奖预测。

## 3. 典型使用流程

1. 用户描述设计任务，例如“为独居老人设计容易坚持使用的健康管理产品”。
2. Agent 提取使用人群、场景、问题、限制条件，检索本地作品库。
3. Agent 展示相关案例及匹配理由；资料不足时，提出年份、类别、奖项和数量等采集条件。
4. 根据用户确定的范围补充采集，生成卡片并更新索引。
5. Agent 对比案例的问题、机制和局限，给出适合当前任务的迁移方向与验证建议。

用户也可以直接给出精确采集条件，或手动录入自己的作品，跳过自然语言映射。

## 4. 首版能力范围

### 4.1 定向采集

| 维度 | Red Dot Design Concept | iF DESIGN STUDENT AWARD |
| --- | --- | --- |
| 年份 | 近三个奖项年度 | 近三个奖项年度 |
| 官网类别过滤 | 支持大类及官网提供的细分类 | 首版不承诺按类别定向采集 |
| 奖项过滤 | 普通奖、至尊奖等，以官网实际名称为准 | 普通学生奖、Best of the Year，以官网实际选项为准 |
| 数量限制 | 支持；按官网默认顺序收集符合条件的前 N 个唯一作品 | 首版不作为必要能力，按选定年份和奖项范围采集 |
| 技术方式 | 优先复用现有直接请求方案，是否为公开接口需核实 | 使用现有 Playwright 浏览器采集方案 |

“近三年”指当前年份及前两年；按本文日期为 2024—2026。官网尚未公布或不可用的年份需明确提示，不能报告为空结果。现有脚本仅支持的年份需扩展后才能满足此要求。

Red Dot 数量不足 N 时，保存实际可得作品并提示差额；数量上限不表示相关性排名。iF 不具备官网类别定向过滤，不代表不能在采集后按作品详情分类和检索。

每次任务展示采集范围、发现数量、成功数量、失败数量及是否完整。失败任务保留进度并允许补采，不将部分成功标为全部完成。网站访问限制、页面改版和网络异常需要分别提示，不承诺绕过访问限制。

当前技术差异属于实现约束：请求更快不等于结果天然完整，浏览器采集也不等于官网完全禁止所有接口访问；完整性仍需分页、数量和详情校验。

### 4.2 本地作品库与增量整理

作品库位于 Skill 包之外，根目录可配置。建议统一结构：

```text
作品库/
├── RedDot/年份/Design Concept/大类/细分类/作品名-编号-奖项等级/
│   ├── image/
│   └── 卡片.md
├── IF/年份/大类/作品名-编号-奖项等级/
│   ├── image/
│   └── 卡片.md
├── Personal/自定义类别/作品名-本地编号/
│   ├── image/
│   └── 卡片.md
└── _index/（自动维护的索引与采集任务记录）
```

Red Dot 没有细分类时直接进入作品目录；iF 缺失类别时进入“待分类”，不得由 Agent 猜测为官网分类。奖项后缀使用稳定的规范名称，例如 `student`、`best`，并在卡片中保留官方原名。

增量规则：

- 以来源平台和官方作品编号识别同一作品，避免重复保存；个人作品使用本地唯一编号。
- 再次采集时补齐缺失图片和字段；刷新官方内容时保留用户笔记。
- 不因一次任务只采集部分作品而删除历史作品。
- 分类或奖项变化时更新索引与路径，避免产生多个无关联副本。
- 索引由卡片生成，可重建；卡片是作品信息的主要存储载体。

个人作品首版支持人工指定类别和标签，缺省归入“待分类”。个人信息、未公开项目默认仅保存在本地，不纳入公开数据集。

### 4.3 分发与数据边界

Skill 包仅包含使用说明、采集脚本、卡片模板、Agent 指令及必要配置，不内置作品数据集。用户可以自行采集，也可以导入独立发布的作品库。

公开作品库是独立交付事项：发布前需核实图片、原文及再分发权限，标明来源和许可。官网可浏览、可采集不等于允许将完整图片与介绍开源；权限不明确时优先发布索引、模板、原创分析和来源链接。

## 5. 知识卡片设计

### 5.1 载体与展示

首版使用 Markdown，作品目录仅保留 `image/` 和 `卡片.md`，不再要求单独的 metadata.json。机器可读字段放在 Markdown 顶部的 YAML frontmatter 中，正文面向设计者阅读。

Markdown 可通过标题、表格、引用和本地图片形成清晰、美观的阅读卡片，但具体视觉样式取决于阅读器，不适合承诺固定排版。首版以 VS Code 等常用 Markdown 阅读器可读、相对路径图片可显示为准；后续可基于同一数据生成 HTML 卡片。

### 5.2 卡片信息架构

| 区域 | 建议内容 | 信息性质 |
| --- | --- | --- |
| 基本信息 | 名称、来源、编号、年份、官方类别、奖项、设计者或团队、来源链接、采集时间 | 官方事实；缺失标注未提供 |
| 作品概览 | 一句话介绍、代表图、官方介绍及中文译文 | 原文摘要与翻译，明确标注 |
| 设计问题 | 服务谁、什么场景、解决什么困难 | 官方陈述优先；推断单独标注 |
| 设计机制 | 核心方法、交互或服务流程、材料或技术特点 | 基于证据的分析 |
| 可迁移启发 | 可借鉴原则、适用条件、迁移边界 | Agent 分析，不冒充官方结论 |
| 个人笔记 | 用户观察、疑问和项目关联 | 用户内容，刷新时保护 |

frontmatter 至少包含 `schema_version`、`source`、`source_id`、`title`、`award_year`、`award_level`、`official_category`、`tags`、`source_url`、`collected_at`、`collection_status`。个人作品允许无奖项年份；官方类别与 Agent 补充标签分字段存储。

图片使用 `image/001.jpg` 等相对路径引用。缺图或字段缺失必须可见，不能把不完整卡片标为完整。采集成功可以先生成基础卡片，深度分析按需补充，避免每次采集都消耗大量模型上下文。

## 6. 设计思维 Agent

### 6.1 检索能力

Agent 先读取轻量索引，再按需打开少量卡片和图片，避免把整个作品库装入上下文。支持按来源、年份、类别、奖项、标签及关键词组合检索，结果包含匹配理由与卡片路径。

System prompt 说明目录约定和工作流程；实际目录查询、索引更新和去重由工具完成，不依赖模型记忆。首版优先采用结构化过滤与关键词检索，语义向量检索作为后续增强项。

### 6.2 自然语言映射与翻译

将用户表达拆解为人群、场景、问题、设计对象和限制条件，再映射到一个或多个官方类别。例如健康相关需求可以建议 iF 的健康类别，但不能仅凭关键词认定为唯一类别。

映射结果展示候选类别、理由及不确定性。涉及明显不同的方向时请用户选择；已给出精确条件时直接执行。映射只能使用采集器真实支持的过滤维度，不将 iF 的本地类别检索伪装为官网类别过滤。

支持官方内容的中文翻译，保留原名称、来源及关键术语；译文与原创分析分开呈现。

### 6.3 激发设计思维

首版采用“问题理解 → 案例比较 → 机制抽象 → 跨场景迁移 → 验证建议”的流程：

1. 明确用户真正想改善的体验及限制条件。
2. 对比若干案例，解释它们各自如何解决问题及有何取舍。
3. 从案例中提炼原则，例如降低操作负担、即时反馈、行为激励或资源循环。
4. 提出若干不同方向，说明如何适配当前人群与场景，避免仅替换外观。
5. 为每个方向列出关键假设、潜在局限及低成本验证办法。

输出建议包含“方向名称、关联案例、借鉴机制、适配方式、待验证问题”。必须区分案例事实与 Agent 假设，不编造用户研究、实验效果或技术可行性证据。

知识迁移方法、启发质量评价及更深入的设计辅导策略仍是研究项，首版以可追溯的案例启发为目标。

## 7. 交互与异常处理

- 开始前：展示数据来源、筛选条件、保存位置；iF 提示需要浏览器且耗时较长。
- 进行中：展示发现、匹配、保存及失败进度，允许中断并保留已完成内容。
- 完成后：说明本次新增、更新、跳过和失败数量，给出卡片入口。
- 无结果：区分没有匹配作品、年份不可用、页面加载失败和分类信息缺失。
- 本地资料不足：说明不足之处，提供放宽条件或补充采集选项。

## 8. 首版验收标准

| 能力 | 验收要求 |
| --- | --- |
| 年份范围 | 两个来源均支持配置的近三年；未公布年份有明确提示 |
| 筛选正确性 | 抽查作品年份、奖项与请求一致；类别采集满足来源支持范围 |
| 数量与完整性 | Red Dot 达到上限或说明不足；列表任务报告分页及未完成项 |
| 增量作品库 | 重复采集不产生重复条目，缺失项可补齐，用户笔记不丢失 |
| 卡片 | 目录结构统一、来源可追溯、本地图片可显示、缺失项可识别 |
| 检索与映射 | 固定测试需求可返回相关案例，并能解释映射和匹配理由 |
| 设计启发 | 建议关联具体案例，包含迁移逻辑与验证问题，事实和推断分离 |
| 数据隔离 | Skill 安装包不含作品库，用户可指定独立数据目录 |

性能先记录典型任务耗时，再设定目标；不在尚未测试时承诺采集速度。启发质量通过设计者试用评估相关性、可操作性和方向多样性，不以生成字数衡量。

## 9. 实施顺序与待定事项

1. **采集与目录统一**：补齐三年支持，验证筛选、分页、数量限制和增量规则。
2. **卡片与索引**：确定字段、迁移现有资料、实现用户笔记保护及索引重建。
3. **Agent 闭环**：实现本地检索、自然语言映射、按需采集和来源可追溯的启发输出。
4. **试用与分发**：用真实设计任务评估效果，再决定公开作品库及扩展来源。

待定事项：个人作品分类体系；卡片代表图选择；Red Dot 官方奖项与类别映射表；现有文件命名迁移策略；图片及原文再分发权限；知识迁移方法与评价量表。

首版不扩展其他设计奖，不建设云端协作平台，也不要求先构建大规模向量数据库。优先把小范围采集、可靠存储和有效设计启发做好。
